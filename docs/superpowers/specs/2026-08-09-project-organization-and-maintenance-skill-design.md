# 项目目录整理与维护 Skill 设计

日期 2026-08-09

> 历史设计与验收记录：文中的 1.3.4/1.4.0、文件移动和个人 Skill 是当时任务事实，不是当前发布指令。当前项目规则以根目录 `AGENTS.md` 为准。

## 目标

精简项目根目录，将不参与程序运行且不需要 Git 保存的本地辅助文件集中到一个目录。同步升级项目版本，并创建个人 Skill，防止以后功能更新时遗漏版本号和使用文档。

- `docs/故障修复报告-2026-08-09.md`
- `GitHub使用教程.md`

以下运行文件保持在项目根目录，路径不变。

- `anime_updater.js`

- `task_state.json`

测试、ffmpeg 工具和已经归档的设计文档保持现有目录结构。

## 目录设计

新建项目根目录下的 `local/`。

```text
local/
├── GitHub使用教程.md
├── 待下载清单.csv
└── 故障修复报告-2026-08-09.md
```

`.gitignore` 忽略整个 `local/`。现有的 `GitHub使用教程.md` 和 `待下载清单.csv` 单文件忽略规则由目录规则取代。

故障修复报告当前已由 Git 跟踪。移动后，它从当前版本的跟踪文件中删除，本地副本保留在 `local/`，旧提交仍保存历史内容。

## 程序行为

默认 CSV 路径由项目根目录下的 `待下载清单.csv` 改为 `local/待下载清单.csv`。

程序写 CSV 前创建目标文件的父目录。该逻辑同时适用于默认路径和通过 `AGE_CSV` 指定的自定义路径。创建失败时沿用现有致命错误处理，不静默跳过清单写入。

计划任务入口、下载目录、追番配置、运行状态和日志路径均不改变。

## 个人 Skill

在 Codex 个人 Skills 目录新建 `maintaining-age-anime`。触发范围限定为维护 AGE 动画自动追更项目，包括修复、功能修改、目录调整、发布和版本提交。

Skill 使用一个简短的完成检查表。

1. 读取 `VERSION`，根据变更范围确定语义化版本。
2. 用户可见行为或路径发生变化时，同步更新 README 和《使用说明》。
3. 每次版本变化时，同时更新 `VERSION`、README 当前版本和《使用说明》版本记录。
4. 提交前搜索旧版本号和旧路径，区分历史记录与仍需更新的现行说明。
5. 运行项目测试并检查 Git 差异，确认 `local/` 内容没有进入提交。

Skill 只包含 `SKILL.md` 和生成的 `agents/openai.yaml`，不增加与维护流程无关的资源。

## Skill 验证

按照 writing-skills 的 RED、GREEN、REFACTOR 流程验证。

- RED 使用一个没有加载新 Skill 的维护场景，记录代理是否会修改代码却遗漏 `VERSION` 或《使用说明》版本记录。
- GREEN 加载新 Skill 后重复同一场景，要求输出包含三处版本同步和旧路径检查。
- REFACTOR 根据遗漏项收紧检查表，再运行验证和 `quick_validate.py`。

验证只在隔离工作区或只读分析场景中进行，不修改当前项目运行状态。

## 测试与验收

自动化测试新增以下行为。

- 默认 CSV 路径位于 `local/待下载清单.csv`
- CSV 父目录不存在时自动创建
- 现有八项下载和时区测试继续通过

完成验收条件如下。

- 项目根目录不再出现指定的三个本地辅助文件
- `local/` 中三个文件均存在
- `git status --ignored` 显示 `local/` 被忽略
- `git ls-files local` 没有输出
- dry-run 能在 `local/` 写入待下载清单
- `VERSION`、README 和《使用说明》都显示 `1.4.0`
- 新 Skill 通过基线对照、加载后复测和格式验证
- 计划任务仍指向根目录中的 `anime_updater.js`
