# 西瓜线路双通道下载设计

## 目标

保持线路 1（西瓜/字节 CDN）为默认优先链路，并让脚本同时正确处理 MP4 直链和 M3U8 播放列表，最终把第 7 集下载为目标 MP4 文件并更新项目进度。

## 方案

线路顺序保持 `1, 2, 3, 4, 5`。每条线路取到地址后先判断地址类型：

- MP4 或其他单文件媒体直链：调用 IDM，传入播放页 Referer 和 User-Agent。
- M3U8 播放列表：调用本机 ffmpeg，使用 Referer 和 User-Agent 下载、合并到临时文件，再原子改名为目标文件。

任何通道在限定时间内未产出达到最小大小且稳定的文件，记录通道、地址类型、文件大小和错误原因，然后进入下一条线路。线路 1 仍然是默认和首选，不会因为增加 M3U8 支持而改变优先级。

## 边界与错误处理

下载器通过依赖注入保留现有测试替身能力。真实 IDM 和 ffmpeg 都使用子进程，并记录启动失败、非零退出码、超时和目标文件状态。M3U8 下载使用 `.part` 临时文件，成功后才写入正式文件；失败残留会被标记或清理，不会被误判为完成。

## 验收

1. 单元测试证明线路 1 的 MP4 仍调用 IDM。
2. 单元测试证明线路 1 的 M3U8 调用 ffmpeg，不调用 IDM。
3. 单元测试证明通道失败后会进入下一线路。
4. 完整测试通过。
5. 真实运行日志出现成功完成记录，目标目录存在第 7 集且大小达到项目阈值，`content.json` 的 `downloaded_end` 更新为 7，文件夹范围同步更新。
