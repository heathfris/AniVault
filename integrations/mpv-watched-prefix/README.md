# mpv 看完后自动更新前缀

> 功能自番仓0.10.0起提供。安装、启用和部署文件哈希请以面板“检查状态”的当前结果为准；每部动漫还需要在 `folder_name` 中包含且仅包含一个 `{watched}`。

## 它会做什么

文件夹名可以同时记录“看到哪里”“下载到哪里”和自定义文字。在番仓的 `folder_name` 中这样写：

```json
"folder_name": "{watched}_{name}{start}-{end} [1080P]"
```

它可以生成：

```text
13_片名1-14 [1080P]
│  │   │    └─ 自定义后缀
│  │   └─ 已下载1到14集
│  └─ 片名
└─ 已看到13集
```

`{watched}`就是允许自动修改的“看到第几集”。脚本只有同时确认下面两件事，才把该集记为看完：

1. 没有暂停、缓冲或拖动时，累计实际播放时间达到视频时长45%；
2. 播放器到达过视频90%的位置。

正常关闭mpv后，只有watched对应的数字改变：

```text
13_片名1-14 [1080P]  →  14_片名1-14 [1080P]
```

片名、下载范围、空格和 `[1080P]` 都原样保留。

它允许倒退。先正常看完第8集，再正常看完第3集，关闭后会变成 `3_`，因为规则是“最后看完”，不是“看过的最大集数”。

## 45%时长 + 90%位置怎样判断

会计算：视频确实在播放时经过的真实秒数。

不会计算：

- 暂停时间；
- 等缓存的时间；
- 拖动进度条的过程；
- 电脑睡眠造成的大段时间跳跃；
- 只有进度到90%、但实际没有播放够45%时长的情况。

以20分钟视频为例，时长门槛为9分钟，位置门槛为18分钟：

| 操作 | 结果 | 原因 |
|---|---|---|
| 1倍速有效播放9分钟，位置也到18分钟 | 达标 | 两道门槛都满足 |
| 2倍速从头完整看完，现实约10分钟 | 达标 | 位置和实际时间都够了 |
| 直接拖到19分钟，再播放2分钟 | 不达标 | 实际时间不够9分钟 |
| 反复播放结尾，累计9分钟且到过18分钟位置 | 会达标 | 两道门槛都满足，但不能证明看过不同画面 |

最后一种是已知限制。要识别是否看过90%的不同画面，需要记录整段视频的覆盖区间，本方案暂不增加这套复杂机制。

## 怎样选择是否启用

这个功能是番仓面板中的一张“mpv观看同步”可选功能卡片，不是必须安装的番仓核心功能。控制分三层：

1. 在番仓里选择是否安装到mpv；
2. 安装后选择总开关启用或停用；
3. 每部动漫再通过 `{watched}` 选择是否参与。

- `folder_name`中恰好有一个 `{watched}`：该动漫选择启用观看改名。
- 没有 `{watched}`：番仓仍可正常下载和更新目录，但mpv助手不会修改它。
- 写了两个或更多 `{watched}`：属于错误配置，番仓和助手都应拒绝改名。
- 没有配置 `folder_name` 的老目录：不会被助手猜测修改。

自定义文字直接写在模板中即可。例如：

```text
[动漫] {watched}_{name} 第{start}-{end}集 [简中][1080P]
```

番仓下载新一集时只更新 `{end}`，保留watched和所有文字；mpv确认看完时只更新 `{watched}`，保留end和所有文字。两边使用同一套模板规则。

## 在番仓中安装

番仓面板现在会显示下面这类功能卡片：

```text
mpv观看同步
状态：未安装 / 已停用 / 已启用 / 需要更新 / 外部改动

[安装或更新] [启用或停用] [检查状态] [卸载]
```

第一次安装时：

1. 番仓检查mpv、Node、项目和下载目录；
2. 显示准备写入的mpv绝对路径；
3. 把Lua和模块配置部署到 `F:\Backend\mpv.lite\portable_config`；
4. 记录部署文件哈希，供以后安全更新和卸载；
5. 默认保持停用，不修改其他mpv脚本，也不迁移旧文件夹。

安装和启用是两个独立动作。安装只是把模块准备好；用户再打开总开关，下一次启动mpv才开始记录。总开关保存在番仓自己的本地状态中，不改部署文件，因此正常启停不会被误报成“外部改动”。项目或mpv目录搬家后，需要回到番仓重新选择路径并安装。

Lua 在mpv关闭时按模块配置中的 `project_root` 调用项目内的 `apply-watched-prefix.js`。因此切换 Git 分支会立即改变下次关闭时使用的后台代码；切换前应确认目标分支已包含当前版本，不要让旧分支退回旧的改名行为。

已有文件夹改用新模板前，先运行番仓现有dry-run核对配置和冲突，再手动把目录改成模板能唯一匹配的名称。程序不会在安装时静默批量迁移旧目录。

## 怎么验证

安装或更新后先用测试目录验证，不直接拿真实追番目录试错：

1. 配置 `"folder_name": "{watched}_{name}{start}-{end} [测试]"`；
2. 用20分钟测试视频验证1倍速有效18分钟且位置到18分钟会改名；
3. 验证2倍速完整看完约10分钟不会改名；
4. 验证seek到19分钟但只播放2分钟不会改名；
5. 验证反复播放末段累计18分钟会达标，并确认日志把它按已知规则记录；
6. 再看完第3集，确认watched可以倒退为3，end和 `[测试]` 不变；
7. 查看 `local/mpv-watched-prefix/watched-prefix.log`，确认每次成功或拒绝都有记录。

正式验收还必须运行项目原有的 `pnpm test`，不能通过跳过或删除测试来换取绿灯。

## 哪些情况不会自动改名

- 视频不在 `D:\idm下载`；
- 当前动漫没有配置含单个 `{watched}` 的 `folder_name`；
- 当前目录不能被该模板唯一匹配，或同时匹配多个动漫；
- 视频时长未知，或播放的是网络地址；
- 有效播放时间不足45%或最大播放位置不足90%；
- 片名不在当前 `content.json`；
- 文件被替换，大小或修改时间发生变化；
- 集数不在文件夹的起始集到下载末集之间；
- 目标文件夹已经存在，或番仓/另一个mpv实例正在持有改名锁；
- mpv崩溃、电脑断电，或者改名安全检查失败。

这些情况应只写日志，不猜、不覆盖、不合并文件夹。

番仓自己把目录中的 `{end}` 改掉，或观看助手把 `{watched}` 改掉时，只要相对视频路径、大小和修改时间不变，跨会话累计仍可继续。用户手动改名后如果无法唯一找到同一文件，则旧累计失效，不进行猜测迁移。

如果上次进程崩溃留下改名锁，助手会先确认锁内PID已经不存在；锁存在至少10分钟后才把它改名保存为stale证据并重试一次。PID状态无法确认时继续拒绝改名。

播放期间只需每秒读取少量mpv状态并更新两个数字；目录扫描只发生在关闭处理、番仓运行或迁移预览时，不会常驻扫描硬盘。具体CPU占用尚未实测，因此当前不承诺百分比。

## 如何停用和卸载

- 临时停用：在番仓关闭总开关，再重新启动mpv。Lua文件仍保留，但不注册监听、不计时、不启动后台助手。
- 再次启用：打开总开关并重启mpv，不需要重新安装。
- 正式卸载：在番仓点击卸载，只移除它自己部署且哈希仍匹配的Lua和模块配置。
- 如果部署文件被用户或其他程序改过，番仓必须显示“外部改动”并拒绝覆盖或删除。
- `local/mpv-watched-prefix` 中的累计状态和日志默认保留；是否清理由用户另行确认。

这里的“像插件”指可以独立安装和开关。第一版不会建设通用插件市场或加载第三方插件；它只是番仓内置的一个可选mpv集成模块。
